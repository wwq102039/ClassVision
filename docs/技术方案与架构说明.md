# 智课眼 · 技术方案与架构说明

> 基于人脸检测与人脸识别的无感课堂考勤与学情分析系统 —— 技术选型、系统架构、核心链路与数据设计。

---

## 一、项目概述

**智课眼**面向高校课堂考勤场景，用摄像头无感完成「到课人数统计 + 学生身份签到」，替代传统点名/刷卡，并沉淀考勤数据做学情分析。

**核心能力**

1. **无感签到**：摄像头画面自动检测人脸、识别身份并签到，学生无需主动操作。
2. **实时人数检测**：教师端实时显示画面中的人数（课堂出勤态势）。
3. **学情分析**：出勤率 / 准时率 / 课堂质量分可视化，支持 Excel 报表导出。
4. **申诉闭环**：学生可对误判缺勤发起申诉，教师审核通过后自动补签。

---

## 二、总体架构

采用前后端分离的三端架构，后端统一提供 REST API，AI 推理在服务端完成。

```
┌───────────────────────────── 展示层 ─────────────────────────────┐
│  管理端（教师 PC 后台）            学生端（移动优先）                │
│  React 18 + Ant Design 5          Vue 3 + Vant 4                 │
│  大屏监控 / 报表 / 人脸库          我的考勤 / 申诉                   │
└───────────────┬──────────────────────────┬─────────────────────┘
                │   HTTP  /api/v1  (JWT)    │
┌───────────────▼──────────────────────────▼─────────────────────┐
│                      后端服务层（FastAPI）                         │
│  ┌────────────┐   ┌──────────────┐   ┌────────────────────┐     │
│  │ API 路由层  │──▶│  业务服务层    │──▶│   AI 推理层          │     │
│  │ api/routes │   │ services/*   │   │ ai/*（检测/特征/比对） │     │
│  └────────────┘   └──────┬───────┘   └─────────┬──────────┘     │
│                          │                     │                │
│  ┌───────────────────────▼─────────────────────▼────────────┐  │
│  │  核心横切层：security(Fernet/JWT) · audit · exceptions      │  │
│  └──────────────────────────────────────────────────────────┘  │
└───────────────────────────────┬────────────────────────────────┘
                                │ SQLAlchemy ORM
┌───────────────────────────────▼────────────────────────────────┐
│                    数据层（SQLite + 加密文件存储）                 │
│   students / courses / class_sessions / attendance / appeal     │
│   storage/faces（人脸特征图）  storage/captures（打卡抓拍）        │
└────────────────────────────────────────────────────────────────┘
```

**分层职责**

| 层 | 目录 | 职责 |
|----|------|------|
| 路由层 | `app/api/routes/` | 参数校验、鉴权依赖注入、返回统一响应 |
| 服务层 | `app/services/` | 考勤、申诉、人脸库、报表等业务编排 |
| AI 推理层 | `app/ai/` | 人脸检测、特征提取、身份比对 |
| 核心横切层 | `app/core/` | JWT 鉴权、Fernet 加密、异常、审计日志 |
| 数据模型层 | `app/models/` | SQLAlchemy ORM 映射 |
| 模式层 | `app/schemas/` | Pydantic 请求/响应模型 |

## 三、技术选型

| 模块 | 技术 | 选型理由 |
|------|------|----------|
| 后端框架 | FastAPI | 异步高性能、自动 OpenAPI 文档、类型友好 |
| ORM | SQLAlchemy 2.0 | 成熟、声明式映射、迁移灵活 |
| 数据库 | SQLite | 零配置、单文件，评委可直接运行 |
| 人脸检测 | YOLOv8n-face（ONNX Runtime）| 轻量、CPU 可实时、跨平台免编译 |
| 人脸识别 | InsightFace / face_recognition / 降级方案 | 高精度（可选），无依赖时自动降级保证可运行 |
| 身份比对 | 余弦相似度 | 特征向量匹配的标准做法 |
| 管理端 | React 18 + Ant Design 5 | 组件丰富、适合数据后台与可视化大屏 |
| 学生端 | Vue 3 + Vant 4 | 移动端优先、暗黑科技风 |
| 安全 | PyJWT + cryptography(Fernet) | 无状态鉴权 + 敏感数据（特征/照片）加密落盘 |

## 四、AI 识别链路

```
图像字节 ──decode──▶ BGR 图像
                      │
                      ▼
              ┌───────────────┐
              │ 人脸检测 Detector │   ONNX yolov8n_face
              │  letterbox + NMS │   → 人脸框列表 [box, score]
              └───────┬───────┘
                      ▼
              ┌───────────────┐
              │ 特征提取 Embedder│   insightface → face_recognition
              │  人脸裁剪 + 编码  │   → 灰度降级（32×32 归一化向量）
              └───────┬───────┘
                      ▼
              ┌───────────────┐
              │  身份比对 Matcher │   余弦相似度 vs 底库
              │  阈值 0.5        │   → 命中学生 / 未识别
              └───────────────┘
```

**多后端降级策略**（保证在任意依赖缺失下仍可运行）

- 检测器：`auto` → ONNX →（可选）ultralytics PT
- 特征提取器：`auto` → insightface → face_recognition → **fallback 灰度降级**
- 底库构建：仅取本课程班级中「已注册人脸特征」的学生

## 五、数据库设计

**实体关系**

```
Student ──< Attendance >── ClassSession >── Course
   │            │
   │            └──(student_id, session_id 唯一约束)
   └──< Appeal >── ClassSession
```

**表结构**

| 表 | 关键字段 | 说明 |
|----|----------|------|
| `students` | student_no(唯一), name, class_name, major, face_embedding(加密), photo_path | 学生与注册人脸特征 |
| `courses` | name, teacher_name, schedule_time, location, class_name | 课程（按班级绑定）|
| `class_sessions` | course_id, session_date, expected_count, actual_count, absent_names(JSON), quality_score, status | 每次课堂 |
| `attendance` | student_id, session_id(唯一约束), sign_time, method, photo_path, status | 签到记录 |
| `appeals` | student_id, session_id(唯一约束), reason, status, comment, reviewed_at | 缺勤申诉 |

**签到状态**：`正常` / `迟到` / `缺勤`；**申诉状态**：`pending` / `approved` / `rejected`；**课堂状态**：`scheduled` / `live`。

## 六、核心业务流程

### 1. 人脸库注册（学生底库）

```
上传照片 → 检测人脸 → 提取特征 → Fernet 加密特征 + 原图 → 落库
```

### 2. 无感签到

```
抓拍画面 → 检测 → 提取特征 → 构建本班底库 → 余弦比对
   → 应到校验（是否本班学生）→ 去重（是否已签到）
   → 迟到判定（签到时间 > 上课时间 + 宽限 10 分钟）
   → 落库 Attendance + 加密保存人脸抓拍（photo_path）
   → 更新实到人数 + 课堂质量分
```

### 3. 实时人数检测

```
教师端打开摄像头 → 每 3 秒抓一帧 → 人脸检测 → 画面人数实时刷新
```

### 4. 学情分析（质量分）

```
课堂质量分 = 出勤率 × 0.7 + 准时率 × 0.3   （归一化 0~1）
出勤率 = 实到 / 应到；  准时率 =（实到 - 迟到）/ 实到
```

### 5. 申诉闭环

```
学生提交申诉 → 教师审核
   ├─ 通过 → 自动补签 Attendance（method="申诉"，status="正常"）
   └─ 驳回 → 记录原因
```

## 七、安全设计

| 能力 | 方案 |
|------|------|
| 身份鉴权 | JWT（HS256），`role` 区分 teacher/student，前端拦截 401 跳登录 |
| 敏感数据加密 | 人脸特征向量、人脸/抓拍照片均用 **Fernet 对称加密** 落盘 |
| 密钥管理 | 优先环境变量 `CV_ENC_KEY`，否则本地生成 `secret.key` 持久化 |
| 接口鉴权 | 教师接口 `require_teacher`，学生接口 `get_current_student` |
| 操作审计 | `audit()` 记录签到/申诉/审核等关键操作 |

## 九、接口规范

**统一响应格式**

```json
{ "code": 0, "message": "ok", "data": { } }
```

- `code = 0` 成功；非 0 为业务错误码（如 `1001` 文件不存在、`1013` 申诉不存在）。

**主要接口**（前缀 `/api/v1`）

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/auth/login` | 登录（teacher/student）|
| GET/POST | `/students` `/courses` `/sessions` | 基础数据 |
| POST | `/faces/import` | 人脸批量导入 |
| POST | `/recognition/detect` | 人脸检测（人数）|
| POST | `/recognition/recognize` | 识别 + 签到 |
| GET | `/sessions/{id}/monitor` | 实时监控统计 |
| GET | `/sessions/{id}/heatmap` | 课堂热力图 |
| GET | `/attendance` `/attendance/mine` | 考勤明细（教师/学生）|
| POST | `/attendance/appeal` | 学生发起申诉 |
| GET | `/appeals` · POST `/appeals/{id}/review` | 申诉列表 / 审核 |
| GET | `/reports/export` | Excel 报表导出 |
| GET | `/static/{subdir}/{filename}` | 解密读取照片 |

## 十一、亮点与创新

1. **多级降级的可运行性**：AI 依赖（insightface/dlib/ultralytics）缺失时自动回退，保证评委零配置即可跑通全流程。
2. **无感签到闭环**：检测 → 识别 → 应到校验 → 去重 → 迟到判定 → 加密抓拍留存，全链路自动化。
3. **隐私保护**：人脸特征与照片全程加密落盘，杜绝明文存储。
4. **学情量化**：以「出勤率 + 准时率」加权计算课堂质量分，支撑教学分析。
5. **三端协同**：教师大屏监控 + 学生移动端 + 后端服务，覆盖考勤全角色。

## 十二、已知限制与后续规划

| 限制 | 说明 | 规划 |
|------|------|------|
| 人数检测为近似 | 仅有人脸检测模型，无独立人体计数 | 增加 YOLOv8 人体检测模型 |
| 人脸识别默认降级 | 未装 insightface 时为近似效果 | 安装 insightface（numpy<2）启用高精度 |
| 静态图未鉴权 | `/static` 依赖随机文件名保护 | 增加带鉴权的图片接口 |
| 迟到判定全局化 | 上课时间取自全局配置 | 增加每节课独立开始时间 |
| 活体检测 | 未实现 | 引入眨眼/动作检测防照片代签 |
